# Implementation Plan: A/B Atomic OTA Update with Automatic Rollback

**Branch**: `002-ab-ota-rauc` | **Date**: 2026-10-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-ab-ota-rauc/spec.md`

## Summary

Turn `beaglebone_black` into a device that can be updated in the field without being lost to a bad
update. The SD card gains two interchangeable 512 MiB OS slots, each holding its own kernel, device
tree and modules, plus a 256 MiB persistent data area and a reserved region holding the
boot-selection state. U-Boot picks a slot from `BOOT_ORDER`, spends one attempt from
`BOOT_<slot>_LEFT` per try, and falls back on its own when a slot runs out. RAUC writes update
bundles only into the slot that is not running; an init script late in boot checks four local
conditions and marks the new slot good, and the hardware watchdog — today pinged forever by the
kernel and therefore useless — is reconfigured so a slot that hangs is reset and retired by the
attempt counter. Every build produces both a flashable factory image and a signed bundle.

Phase 0 settled seven questions ([research.md](research.md)): MBR rather than GPT, which forces the
state into a reserved region; the environment moves out of FAT to raw offsets 0x80000/0xA0000 with
a redundant copy; ext4 mounted read-only now with squashfs deferred; one attempt counter, not the
two currently configured; mark-good and watchdog arming under BusyBox init; `plain` bundles built
by `host-rauc`; and a two-tier development CA rather than a single self-signed key, because that
choice is the one that cannot be changed later without reflashing every device.

## Technical Context

**Language/Version**: POSIX `sh` (init script, `post-image.sh`, check additions), GNU Make, U-Boot
environment script (`ENV_SOURCE_FILE` text file), Kconfig-format board configs; Buildroot
2026.08.x and the Debian bookworm build container, both unchanged

**Primary Dependencies**: `rauc` 1.15.2 and `host-rauc` from the pinned Buildroot tree (pulls
`libglib2`, `openssl`, `squashfs`); `uboot-tools` with `BR2_PACKAGE_UBOOT_TOOLS_FWPRINTENV`;
`host-uboot-tools` for `mkenvimage`; `genimage`, `dosfstools`, `e2fsprogs`, `mtools` already
present. BusyBox `watchdog` applet already enabled. The `openssl` command line becomes a
build-environment dependency and is added to the `Dockerfile` explicitly, rather than relied on as
a transitive dependency of `ca-certificates`. No internal package, no new `.hash` file: kernel
6.18.38 and U-Boot 2026.07 keep their versions.

**Storage**: one SD card, MBR, four primaries plus a reserved region —
`reserved env 0x80000+0xA0000` / `p1 boot FAT 32 MiB` / `p2 rootfs.A 512 MiB` /
`p3 rootfs.B 512 MiB` / `p4 data 256 MiB`; about 1.3 GB of image, 2 GB minimum medium. Slot
filesystem is a 128 MiB read-only ext4. See [contracts/storage-layout.md](contracts/storage-layout.md).

**Testing**: no unit framework (Principle IV). Verification is `make check` extended to the new
layout and scripts, plus the hardware scenarios in [quickstart.md](quickstart.md): a flash-and-boot
run, an update, five power cuts mid-install, a deliberately broken bundle, a deliberately hung
slot, and four rejected bundles.

**Target Platform**: BeagleBone Black (AM335x, Cortex-A8), SD card, serial console on J1 at
115200 8N1. On-board eMMC untouched.

**Project Type**: embedded Linux build system — Buildroot `BR2_EXTERNAL` tree, no application code

**Performance Goals**: boot no slower than 11.50 s + 10% = **12.65 s** from the U-Boot SPL banner to
the login prompt, measured as in `docs/boot-baseline-beaglebone-black.md` (SC-008); update complete
within 5 minutes of one command plus one reboot (SC-001). Dropping `bootdelay` from the measured
2.08 s is available as headroom if slot selection costs anything.

**Constraints**: the ROM boots only from an MBR medium with a FAT partition, so GPT is unavailable
and all four primaries are spoken for; `ENV_OFFSET` must be set explicitly because its
`ARCH_OMAP2PLUS` default of 0x260000 lands inside partition 1; the running slot is read-only;
exactly one attempt counter may be active; the bootloader area is never written by an update; no
private key in the repository; `/workspace` stays a single mount; build as the unprivileged `br`
user.

**Scale/Scope**: one board adopts A/B; the shared layer must let a second board adopt it by adding
board-local files only (FR-029), verified by review until a second board exists (FR-025).

## Constitution Check

*GATE: must pass before Phase 0 research. Re-checked after Phase 1 design — still passing.*

| Principle | Verdict | Notes |
|---|---|---|
| I — Upstream immutable | **PASS** | No change under `buildroot/`. U-Boot and kernel are customised through `BR2_TARGET_UBOOT_USE_CUSTOM_CONFIG` and `BR2_LINUX_KERNEL_USE_CUSTOM_CONFIG` with files under `board/ota/beaglebone_black/`, generated by `make uboot-update-defconfig` and `make linux-update-defconfig`, not by hand-written fragments. Slot-selection logic is a text environment file in the external tree (FR-005). |
| II — Reproducible, integrity-checked | **PASS** | Every new dependency is an upstream Buildroot package carrying its own hash; kernel and U-Boot versions are unchanged so `patches/*/*.hash` needs no edit. `BR2_DOWNLOAD_FORCE_CHECK_HASHES` stays on. Versions stay pinned. Single `/workspace` mount unchanged. |
| III — Small, declarative, idiomatic | **PASS** | Defconfig changes go through `menuconfig` and `savedefconfig`; scripts are POSIX `sh` with `set -eu`, quoted expansions and Buildroot-exported variables; no speculative abstraction — one init script, one post-image step, one make target. |
| IV — Verification (non-negotiable) | **PASS with obligations** | This change touches partition layout, bootloader environment, kernel configuration, bootargs and init, so the hardware boot smoke test is mandatory and a green `make check` is explicitly not sufficient. `make check` must also grow: new scripts linted, the four-partition-plus-reserved-region layout asserted, the kernel inside the slot rather than the boot partition asserted. Evidence goes in the PR. |
| V — Consistent developer and operator experience | **PASS with obligations** | A new `make ota-dev-keys` target extends the documented make surface, so `README.md`, `CLAUDE.md` and `make help` change in the same commit. Board parity holds: the board keeps `genimage.cfg`, `post-image.sh` and `rootfs_overlay/`, still reuses `board/ota/common/`, still produces one flashable artifact, and the README gains the update and rollback procedures. `/etc/build-info` and `/etc/issue` stay. |
| VI — Performance and footprint budgets | **PASS with obligations** | Partition sizes change, so every figure in the README's footprint paragraph is re-measured: both slots, the boot partition, the data area, `sdcard.img`, the bundle. Boot time is re-measured against 11.50 s. The environment is now written on every boot attempt; that cost is part of the boot-time measurement. |
| VII — Secure and safe defaults | **PASS** | Nothing in the repository is a credential: `make ota-dev-keys` generates a development CA and a bundle-signing pair into the gitignored `keys/dev/`, and neither private key nor either certificate is committed (research R7, [contracts/signing-chain.md](contracts/signing-chain.md)). The keyring holds the CA, so a compromised signing key is answered by issuing a new certificate instead of reflashing. Both certificate subjects say `NOT FOR PRODUCTION`. Bundles are signed and verified before anything is written. `dd` instructions keep their device warning. Passwordless root is unchanged and remains a development-image property; a hardened variant stays out of scope. |

No gate is violated, so the Complexity Tracking table below records only the two configuration
files this feature has to introduce and why nothing smaller would do.

**Structure Decision**: nothing moves outside the existing `BR2_EXTERNAL` layout. The only
board-independent new file is the health init script, which belongs in `board/ota/common/` because
FR-029 requires a second board to adopt A/B by adding board-local files only; everything that names
a device, an offset or a slot is board-local. The two deletions are not cleanup for its own sake:
the baseline log shows the board boots through `extlinux.conf` and never reads `uEnv.txt`, and both
are replaced by the slot-selection script.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| A custom U-Boot configuration file (`uboot.config`) replacing the plain `am335x_evm` defconfig | The environment must leave FAT for raw redundant storage, the slot-selection script must be the default environment, and the inherited second boot counter must be switched off. None of that is expressible without changing U-Boot's configuration. | A config *fragment* would be shorter, and `BR2_TARGET_UBOOT_CONFIG_FRAGMENT_FILES` exists, but the constitution's Technical Constraints require `*_USE_CUSTOM_CONFIG` with a generated file rather than hand-edited fragments. |
| A custom kernel configuration file (`linux.config`) replacing the plain `omap2plus` defconfig | `CONFIG_WATCHDOG_HANDLE_BOOT_ENABLED=y` with an open timeout of 0 makes the kernel ping the bootloader's watchdog forever, so a hung slot is never reset and FR-032 cannot be met. The driver is also a module, leaving the early boot window uncovered. | Leaving the kernel alone was the plan until the baseline showed the watchdog is decorative. Relying on the attempt counter alone fails, because nothing reboots a hung device for the counter to act on. |
